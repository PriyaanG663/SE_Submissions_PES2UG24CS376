# Lab 5 Reflection: Static Code Analysis

### 1. Which issues were the easiest to fix, and which were the hardest? Why?
* **Easiest to fix:** The stylistic and formatting issues flagged by **Flake8** and **Pylint**—such as adding two blank lines between functions (`E302`), wrapping lines to stay under 79 characters (`E501`), renaming `printAlerts` to `print_alerts` (`C0103`), and replacing string concatenation with f-strings (`C0209`)—were the easiest. They required purely mechanical, localized edits without altering program behavior.
* **Hardest to fix:** Resolving the combination of **logical domain flaws** and **structural Pylint warnings** (`W0603 global-statement` alongside unvalidated inputs) required the most thought. For example, static analyzers did not flag that `change_interval(-30)` set a negative service window (causing newly registered machines to immediately appear overdue), that `register_asset("FL-01", "Crane")` silently overwrote the existing Forklift, or that unvalidated user input in `update_service_date()` caused an unhandled `ValueError` later inside `due_for_inspection()`. Fixing these required redesigning validation inside `register_asset()`, `update_service_date()`, and `change_interval()`, as well as refactoring `SERVICE_INTERVAL_DAYS` into a configuration dictionary to avoid mutating global variables with the `global` keyword.

### 2. Did the static analysis tools report any false positives? If so, describe one example.
While none of the warnings were strictly erroneous, **Pylint's `C0103 (invalid-name)`** and **`W0603 (global-statement)`** on `SERVICE_INTERVAL_DAYS` bordered on a contextual false positive for a small script. Initially, `SERVICE_INTERVAL_DAYS = 90` was named in `UPPER_CASE` at the module level, which satisfies Pylint's module-level constant naming convention. However, because `change_interval()` reassigned it using `global SERVICE_INTERVAL_DAYS`, Pylint penalized the use of `global`—and if renamed to `snake_case` to reflect its mutability, Pylint can flag it as a non-constant module variable name. Similarly, **Bandit's `B101 (assert_used)`** flagged `assert len(assets) > 0, "no assets"`. In a quick demonstration script, an `assert` is often used as a sanity check by developers, though Bandit is technically right that `assert` statements are stripped when running Python with the `-O` optimization flag.

### 3. How would you integrate static analysis tools into your actual software development workflow?
1. **Local IDE & Editor Integration:** Configure VS Code / Neovim extensions to run **Flake8**, **Pylint**, and **Bandit** in real time on file save so style, quality, and security issues are caught while writing code.
2. **Git Pre-Commit Hooks:** Use the `pre-commit` framework (`.pre-commit-config.yaml`) to automatically run `flake8`, `bandit`, and `pylint` on staged `.py` files before allowing a `git commit`, preventing defective code from ever entering version control.
3. **CI/CD Pipeline Quality Gates:** Add a GitHub Actions workflow triggered on `push` and `pull_request` that executes all three tools. Configure the pipeline to fail the build if Flake8 or Bandit reports any issues or if Pylint drops below a strict threshold (e.g., `--fail-under=9.5`).

### 4. What tangible improvements did you observe in the code quality, readability, or potential robustness after applying the fixes?
* **Security & Resource Safety:** Replacing `tempfile.mktemp()` with `tempfile.NamedTemporaryFile()` eliminated a time-of-check to time-of-use (TOCTOU) race condition, and using `with open(..., encoding="utf-8")` guaranteed that file descriptors are deterministically closed even if an exception occurs during JSON serialization.
* **Crash Resilience & Error Visibility:** Replacing the bare `except:` with specific `KeyError` and `ValueError` handlers—combined with `datetime.strptime()` validation and structured `logging`—ensured that invalid asset IDs (`XX-99`) or malformed user dates no longer fail silently or crash `due_for_inspection()` later in execution.
* **Data Integrity & Readability:** Fixing the mutable default argument (`logs=None`), rejecting empty/duplicate asset IDs and negative service intervals, adding docstrings, and adhering to PEP 8 made the control flow self-documenting, predictable, and achieved a **10.00/10** Pylint rating with zero Bandit or Flake8 warnings.
